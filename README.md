# Manuscript AI — سامانه فرانت‌اند بازشناسی خط کهن و ارزیابی معماری

سامانه مستقل فرانت‌اند (React + TypeScript + Vite) جهت پژوهش دانشگاهی، مدیریت کاتالوگ اسناد کهن، بازشناسی متن (HTR/OCR)، تصحیح انتقادی دسته‌جمعی نسخ خطی فارسی و عربی، به همراه **میزکار بررسی معماری و تحلیل تئوریک مقیاس‌پذیری سرویس بک‌اند** ([mohammaden03/university-project-backend](https://github.com/mohammaden03/university-project-backend)).

---

## ۱. ویژگی‌های کلیدی فرانت‌اند (Frontend Capabilities)

- **معماری مستقل فرانت‌اند (Decoupled SPA):** کلاینت خالص React 19 بر بستر Vite بدون وابستگی به وب‌سرورهای درون‌برنامه‌ای Express یا دیتابیس‌های موقت داخلی.
- **رابط کاربری راست‌چین (RTL) و تایپوگرافی اصیل:** بر پایه قلم وزیرمتن (Vazirmatn)، رنگ‌بندی کهن‌نگاری ایرانی (کهربایی، سنگی و کاهی) و پشتیبانی از تم تاریک و روشن.
- **میزکار بازشناسی (HTR Workspace):**
  - نگارخانه بررسی برگه‌ها (Folios) با وضوح بالا.
  - ابزارهای بصری: زوم، چرخش ۹۰ درجه، تقویت‌کننده کنتراست مرکب، و استریم مستقیم امن باینری با Blob بدون افشای توکن در Query String.
  - ویرایشگر متن با پشتیبانی از حل تعارض خوش‌بینانه (`expectedVersion`) و مدیریت خطای ۴۰۹ (Concurrency Conflict).
  - درختچه تاریخچه بازبینی‌ها (Revision History) و گردش‌کار تایید علمی.
- **موتور جستجوی پیشرفته متون:** نرمال‌سازی نویسه‌های کهن فارسی و عربی (یکسان‌سازی ی/ک، حذف تنوین، اعراب و تطویل/کشیده) و استخراج برش‌واژه‌های منطبق.
- **مدیریت خطای شبکه و تاب‌آوری آفلاین:** اعلام وضعیت صریح در زمان عدم دسترسی به بک‌اند بدون جعل داده‌های فرضی.

## ۲. بررسی ساختاری معماری بک‌اند و تحلیل تئوریک مقیاس‌پذیری (Architecture Analysis)

در تحلیل ساختاری سرویس‌های بک‌اند، پنج گلوگاه بالقوه مقیاس‌پذیری شناسایی گردیده و راهکارهای بهینه‌سازی در قالب پیش‌نمایش پچ و پروپوزال ارائه شده است:

| شناسه | گلوگاه عملکردی | اولویت | شرح اثر بر مقیاس‌پذیری | راهکار پیشنهادی برای استقرار در بک‌اند | هدف معماری (برآورد تئوریک) |
|:---:|:---|:---:|:---|:---|:---|
| **B1** | مسدودسازی Event Loop با پردازش همگام HTR | بحرانی | تاخیر درخواست‌ها در زمان استنتاج‌های طولانی یادگیری ماشین | معماری صف کار ناهمگام (BullMQ + Redis) با کارگران مجزا | جداسازی نخ وب‌سرور از پردازش‌های سنگین GPU |
| **B2** | استریم باینری سنگین تصاویر با پروسه اصلی | بالا | مصرف بالای بافرهای حافظه RAM نودجی‌اس | واگذاری مستقیم استریم فایل‌ها به Object Store (مانند S3/MinIO) و CDN | کاهش بار حافظه پروسه وب‌سرور |
| **B3** | جستجوی تمام‌متن خطی $O(N)$ در حافظه | بالا | افزایش زمان پاسخ‌دهی جستجو با رشد تعداد نسخه‌ها | استفاده از نمایه Trigram در PostgreSQL (`pg_trgm`) | بهره‌گیری از ایندکس پایگاه‌داده به جای پیمایش درون‌حافظه |
| **B4** | عدم مدیریت متمرکز کانکشن‌های دیتابیس | متوسط | احتمال اشباع اتصالات PostgreSQL در زمان پیک بار کارگاهی | استفاده از لایه Connection Pooling (نظیر PgBouncer) | مدیریت بهینه اتصالات پایگاه داده |
| **B5** | قفل‌گذاری خوش‌بینانه در سطح کل صفحه | متوسط | پس‌زدن تغییرات همزمان در سطرهای غیرمتداخل | تفکیک کنترل همزمانی به سطح سطر (`Line-Level Concurrency`) | کاهش تداخل کاذب در ویرایش گروهی |

> **تذکر علمی و سلب ادعا:** ارقام و نمودارهای ارائه‌شده در بخش شبیه‌ساز میزکار بهینه‌سازی، مدل‌های برآورد تئوریک و اهداف تحلیلی هستند و به عنوان بنچمارک اندازه‌گیری‌شده در کلاستر عملیاتی تلقی نمی‌شوند. سنجش پرفورمنس قطعی مستلزم استقرار پچ‌ها در محیط سرور اختصاصی و آزمون با ابزارهایی نظیر k6 یا Autocannon تحت بار واقعی است.

## ۳. نحوه راه‌اندازی و پورت‌های اجرایی (Ports & Execution)

### تفکیک پورت‌ها و جلوگیری از تداخل (Port Architecture)
جهت جلوگیری از تداخل پورت میان سرویس بک‌اند و کلاینت فرانت‌اند:
- **سرویس بک‌اند (NestJS REST API):** پورت پیش‌فرض `3000` (`http://localhost:3000/api/v1`).
- **پیش‌نمایش فرانت‌اند (Vite Preview / Production Serving):** پورت پیش‌فرض `4173` (`http://localhost:4173`).
- **سرور توسعه فرانت‌اند (Vite Dev):** پورت `3000` در کانتینر ابری یا `5173` در اجرای محلی.
- **نکته مهم:** مقدار `VITE_API_BASE_URL` همواره به سرویس بک‌اند (پورت ۳۰۰۰) اشاره دارد، نه پورت پیش‌نمایش استاتیک فرانت‌اند (۴۱۷۳).

### متغیرهای محیطی
یک فایل `.env.example` در ریشه مخزن وجود دارد:
```bash
# آدرس سرویس مستقل بک‌اند (NestJS REST API)
VITE_API_BASE_URL=http://localhost:3000/api/v1

# مبداهای مجاز اختیاری جهت اتصال API کلاینت
VITE_ALLOWED_API_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

### دستورات توسعه و ساخت
```bash
# نام بسته: manuscript-ai-frontend
npm install

# اجرای سرور توسعه Vite
npm run dev

# بررسی سلامت کد و تست‌های واحد کلاینت (Node Test Runner)
npm test

# بررسی نوع‌ها بدون کامپایل (TypeScript No-Emit)
npm run lint

# بیلد نهایی فایل‌های استاتیک مستقل فرانت‌اند (تولید خروجی در dist/)
npm run build

# پیش‌نمایش خروجی بیلد استاتیک روی پورت غیرمتداخل ۴۱۷۳
npm run preview
# یا
npm run start
```

## ۴. امنیت احراز هویت، توکن‌ها و محافظت در برابر نشت اطلاعات

1. **ایزوله‌سازی توکن در سطح نشست (Session-Scoped Storage):**
   توکن‌های احراز هویت JWT با هدر Bearer منحصراً در `sessionStorage` نگهداری می‌شوند و با بستن تب مرورگر یا خروج کاربر امحا می‌گردند. هیچ رمزی در حافظه مرورگر ذخیره نمی‌شود.
2. **محافظت در برابر نشت توکن به دامنه‌های بیگانه (Origin Whitelist Protection):**
   کلاینت Axios هدر `Authorization: Bearer <token>` را **فقط و فقط** به مبداهای مجاز و مورد اعتماد (مسیرهای نسبی، لوپ‌بک لوکال، یا دامنه پیش‌فرض `VITE_API_BASE_URL`) ارسال می‌کند. اگر درخواستی به دامنه‌ای متفرقه ارسال شود، توکن برای حفظ امنیت به طور خودکار حذف می‌شود.
3. **اعتبارسنجی سخت‌گیرانه URLهای پویا:**
   هرگونه تنظیم آدرس در صفحه تنظیمات با توابع امنیتی ارزیابی شده و پروتکل‌های ناامن (`javascript:`, `data:`, `file:`) و آدرس‌های پروتکل-نسبی (`//evil.com`) مسدود می‌گردند.
